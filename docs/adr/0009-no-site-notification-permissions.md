# Web 通知にサイト別の許可管理を設けない

Koma の Web 通知フックは `Notification.permission` と `Notification.requestPermission()` に対してサイト別の許可状態を持たず、常に `"granted"` を返す。

## 背景と理由

- **開いている間しか通知が来ない**: 対象は作業面上に開いている Web Koma からの通知のみで、バックグラウンドの Service Worker や Web Push は対象外としている。不要になった場合は Koma を閉じるか Drawer へしまえば通知は止まる。
- **OS 通知センターへ割り込まない**: 通知は Profile 内の通知一覧とウィンドウ内のトーストに留まり、OS 全体の妨げにならないため、サイト単位の許可ダイアログや拒否設定を永続化するコストに見合う利点が薄い。
- **作業面の合図を取りこぼさない**: ユーザー自身が作業面に置いている Koma からの通知を都度ブロックせず、そのまま受け取れる方が作業面として自然である。

## 見直し条件

開いたままにする必要があるサイトからの通知過多が実用上の問題になる場合、またはバックグラウンドの Web Push や OS 通知センター連携を導入する場合は、サイト別の許可管理や Koma 単位のミュートを再検討する。
